# ProfileForge Roadmap

The engineering architecture is now mature and stable. From this point onward, **we stop measuring success by internal complexity and start measuring success by external adoption.**

## Milestones
- `[x]` **v1.x Rendering API Freeze**: Layer 4 abstraction completed (2026-08-08). The architecture is stable, deterministic, and fully separated. All future work must focus on ecosystem growth.

## Key Performance Indicators (KPIs)

Our goal is not "better architecture", but "people using ProfileForge to build beautiful profiles."
We track:
- GitHub Stars & Forks
- Contributors (Issues opened/closed)
- PyPI downloads
- GitHub Action usage
- Studio users & Documentation traffic
- External Themes, Widgets, Templates, and Connectors

---

## Phase A — Adoption (Current Priority)

**Focus: Publish v1.0.0 and gather feedback.**
- Collect user feedback and fix bugs.
- Improve onboarding and documentation.
- Record demo videos and publish tutorials.
- *No major features or architectural rewrites.*

## Phase B — Ecosystem

**Focus: Empower the community.**
- Encourage the community to build and share themes, widgets, templates, and connectors.
- The community should become the largest source of new functionality, while the core remains stable.

## Phase C — ProfileForge Studio

**Focus: The Flagship Experience.**
- Turn the Studio into the easiest way on the internet to build a GitHub profile.

## Phase D — Registry

**Focus: The Marketplace.**
- Only after a healthy ecosystem exists, launch an official registry for themes, widgets, templates, and connectors.
- Think of it as the "VS Code Marketplace" for ProfileForge.

---

> *"If multiple users independently encounter the same limitation, solve it in the core. Otherwise, keep the core stable and let extensions handle niche needs."*
